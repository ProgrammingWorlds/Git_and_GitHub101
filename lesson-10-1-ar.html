الوحدة 10 · الدرس 10.1

التراجع عن التغييرات قبل الـ commit

Undo changes before you commit

أهداف التعلم

  • أن تتخلص من تعديل ملف.
  • أن تُخرج ملفًا من staging.
  • أن تحفظ العمل جانبًا بـ stash.

المتطلبات المسبقة

الوحدة 4.

مقدمة

أغلب الأخطاء تحدث قبل الـ commit، وهي الأسهل إصلاحًا.

الشرح

git restore index.html يرمي تعديلاتك في ذلك الملف ويعيده إلى آخر commit. لا يمكن التراجع عن ذلك لأن Git لم يحفظ تلك التعديلات.

git restore --staged style.css يُخرج الملف من منطقة staging ويُبقي تعديلاتك. وهو عكس git add.

نفّذ git status أولًا لتعرف أي الملفات في staging وأيها لا.

git stash push -m "work in progress" يضع تعديلاتك غير المحفوظة في درج آمن ويعطيك شجرة نظيفة. git stash list يعرض الأدراج وgit stash pop يعيد الأحدث.

استخدم stash عندما تريد تبديل الفرع أو السحب ولست جاهزًا للـ commit.

في VS Code: مرّر المؤشر على ملف في Source Control؛ زر ↶ Discard Changes يستعيده، وزر − يُخرجه من staging. التجاهل يطلب تأكيدًا وهو أيضًا لا رجعة فيه.

تشبيه من الحياة

الـ restore ممحاة تعيد الصفحة إلى آخر نسخة مطبوعة. والـ stash أن تدفع مكتبك الفوضوي إلى درج لوقت لاحق.

مخطط توضيحي

الأوامر

git restore FILE
git restore --staged FILE
git stash push -m "msg"
git stash pop

الشكل 1 يعرض restore وإخراج الملف من staging.

أخطاء شائعة وحلولها

استخدام restore على عمل تريد الاحتفاظ به.استخدم stash أو commit أولًا.
الخلط بين restore وrestore --staged.الأول يرمي التعديلات والثاني يُخرج من staging فقط.
نسيان العمل المخزّن.تحقق من git stash list.

تمرين عملي

عدّل index.html وتخلّص من التعديل. ثم أضف style.css إلى staging وأخرجه.

النتيجة المتوقعة

يعرض git status أن index.html نظيف وstyle.css معدّل وليس في staging.

اختبر فهمك

1. ماذا يفعل git restore FILE؟
2. ماذا يفعل restore --staged؟
3. git stash لـ…

الإجابات

  • يرمي تعديلاتك — لا رجعة فيه.
  • يُخرج من staging ويُبقي التعديلات — يلغي git add.
  • حفظ العمل جانبًا — pop يعيده.

الخلاصة

restore يرمي التعديلات، وrestore --staged يُخرج من staging، وstash يركن العمل.

مصطلحات أساسية

restoreإعادة ملف إلى حالة محفوظة
unstageإخراج من منطقة staging
stashتخزين مؤقت للتعديلات
