Introduction

Git sees your folder but does not track anything until you tell it to. Here you create the first files and watch how Git reports them.

Explanation

In VS Code choose File → Open Folder and open my-first-project. Create three files: index.html, style.css and README.md. Paste the contents below and save each file. A dot on a tab means it is not saved yet.

</head>

  <h1>Hello, Git!</h1>
  <p>This is my first project.</p>
</body>
</html>

# My First Project

A small website I use to learn Git and GitHub.

Run git status. Git lists the three files under Untracked files: it sees them but is not tracking them.

The four states: Untracked (new, unknown to Git), Modified (tracked file changed), Staged (chosen for the next commit), Committed (safely stored in history). In VS Code, untracked files show a U beside the name and modified files show an M. You will stage and commit them in Module 4.

Real-world analogy

Untracked files are guests who walked into the house. Git sees them, but nobody has put them on the guest list yet.

Commands

git status

Run it after creating and saving the files. You can also copy the finished files from the course folder starter-project/.

Common mistakes and solutions

Files not saved.Save with Ctrl+S. Git only sees saved changes.
Files created outside the project folder.Check they are inside my-first-project.
Expecting git status to track the files.It only reports. Tracking starts with git add.

Practical exercise

Create the three files, save them, and run git status.

Expected result

All three files appear under “Untracked files”, as in Figure 1.

Knowledge check

1. What state is a brand-new file?
2. What does U mean in VS Code?
3. Which state comes after staged?

Answers

  • Untracked — Git has not seen it before.
  • Untracked file — U marks an untracked file.
  • Committed — Commit stores staged changes in history.

Summary

You created index.html, style.css and README.md, saw them as untracked, and learned the four file states.
