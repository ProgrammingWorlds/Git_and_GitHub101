MODULE 01 · LESSON 1.3

Understanding the Git workflow

فهم سير عمل Git

Learning objectives

  • Name the four places a change can live.
  • Recognize untracked, modified, staged and committed files.
  • Explain add → commit → push.

Prerequisites

Lessons 1.1 and 1.2.

Introduction

Git does not save everything automatically. You choose what to save and when. That choice happens in stages, and learning them makes every later command easy to understand.

Explanation

Working directory: your project folder, where you edit files.

Untracked files are new files Git has never seen. Modified files are tracked files you changed since the last commit.

Staging area: a waiting room. You place the changes you want in the next commit here. The command is git add.

Local repository: the history on your computer. git commit saves the staged changes as a new commit.

Remote repository: the copy on GitHub. git push sends your new commits there.

The commit history is the list of all commits. Remember: staging is not committing, and committing is not pushing. Each is a separate step.

Real-world analogy

Packing a parcel: you edit in your room (working directory), put the items you chose into the box (staging), seal and label it (commit), then send it by post (push).

Commands

You will learn these commands in Modules 4 and 5. For now, just recognize them: git add, git commit -m "message", git push.

Common mistakes and solutions

Thinking add saves the work.It only prepares changes. Nothing is saved until you commit.
Thinking commit uploads to GitHub.Commit saves on your computer only. Push uploads.
Expecting new files to be tracked automatically.New files are untracked until you add them.

Practical exercise

Imagine you edit index.html, then run git add index.html, then git commit -m "Add homepage". Write which stage the change is in after each of the three actions.

Expected result

After editing: modified, in the working directory. After add: staged. After commit: saved in the local repository, not yet on GitHub.

Knowledge check

1. Which command sends commits to GitHub?
2. A brand-new file Git has never seen is…
3. Does git add create a commit?

Answers

  • git push — push uploads commits to the remote repository.
  • Untracked — New files are untracked until you add them.
  • No, it only stages changes — Staging prepares changes. Commit creates the snapshot.

Summary

A change travels from the working directory to the staging area (add), to the local repository (commit), and to the remote repository (push).
