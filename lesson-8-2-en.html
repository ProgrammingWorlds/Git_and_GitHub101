Fetching changes

جلب التغييرات

Learning objectives

  • Explain fetch.
  • Compare local and remote.
  • Read “behind” and “ahead”.

Prerequisites

Lesson 8.1.

Introduction

Fetch downloads new work from GitHub without changing your files. It is the safe way to look first.

Explanation

Someone edited the README on GitHub. Your computer does not know yet.

git fetch updates your remote-tracking branches such as origin/main. Your own main and your files stay untouched.

git status now says your branch is behind origin/main by one commit.

Inspect with git log --oneline main..origin/main (what you do not have) or git diff main origin/main.

“Ahead” means you have commits to push. “Behind” means GitHub has commits to pull. Both at once is “diverged”.

In VS Code, the status bar shows arrows with counts. The Source Control menu (…) has a Fetch command.

Real-world analogy

Fetch is checking the mailbox and reading the letters at the door without bringing them into your room.

Common mistakes and solutions

Thinking fetch changes your files.It does not. It only updates origin/*.
Forgetting to fetch before comparing.Status uses your last known copy of origin.
Panic at “diverged”.Pull and resolve (Lesson 8.3).

Practical exercise

Edit README.md on GitHub (the pencil icon), commit there, then fetch locally.

Expected result

git status says you are behind by 1 commit and your README is unchanged.

Knowledge check

1. Does fetch change your working files?
2. What does “behind by 1” mean?
3. Which branch is updated by fetch?

Answers

  • No — It only updates remote-tracking branches.
  • GitHub has one commit you lack — You need to pull.
  • origin/main — The remote-tracking branch.

Summary

Fetch looks at GitHub safely. Status then tells you if you are behind or ahead.

Key vocabulary
