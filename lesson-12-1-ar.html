الوحدة 12 · الدرس 12.1

التخطيط وبدء المشروع

Plan and start the project

أهداف التعلم

  • أن تقرأ وصف المشروع.
  • أن تنشئ المستودع.
  • أن تخطط للفروع والمهام.

المتطلبات المسبقة

الوحدات 1–11.

مقدمة

ستبني موقع Portfolio صغيرًا وتديره كمشروع فريق حقيقي.

الشرح

الوصف. موقع من صفحة واحدة بأربعة أقسام: Home وAbout وProjects وContact. HTML وCSS عاديان بلا frameworks.

المستودع. أنشئ portfolio-website على GitHub (عام وبدون README) ثم نفّذ أوامر الشكل 1. استخدم git init -b main ليكون الفرع الأول main.

أضف بنية بدئية: index.html وstyle.css وREADME.md و.gitignore.

الخطة. اكتب المهام كفروع: feature/home وfeature/about وfeature/projects-section وfeature/contact وdocs/readme.

القواعد. لا commit على main بعد أول رفع؛ كل تغيير عبر pull request؛ رسائل commit محددة.

يمكنك استخدام Issues في GitHub لسرد المهام وكتابة Closes #1 في PR لإغلاق واحدة.

ماذا يحتاج الموقع. شريط تنقل، وقسم hero فيه عنوان وزر، وقسم About، وقسم Projects ببطاقات، وقسم Contact، وتذييل. اجعله متجاوبًا بوسم viewport وشبكة مرنة. المجلد final-project/starter فيه الهيكل الفارغ وfinal-project/solution فيه مثال كامل للمقارنة بعد الانتهاء.

تشبيه من الحياة

أنت المهندس ومدير الموقع معًا: الخطة أولًا ثم البناء.

مخطط توضيحي

الأوامر

git init -b main
git remote add origin URL
git push -u origin main

الشكل 1 يعرض الإعداد.

أخطاء شائعة وحلولها

إنشاء المستودع مع README ثم رفع تاريخ مختلف.أنشئه فارغًا أو انسخه بـ clone.
البدء بلا خطة.اسرد الفروع أولًا.
العمل على main.فرع لكل مهمة.

تمرين عملي

أنشئ المستودع وارفع البنية الأولية.

النتيجة المتوقعة

يعرض GitHub ملفاتك وcommit واحدًا على main.

اختبر فهمك

1. كم قسمًا يطلب الوصف؟
2. أين تذهب التغييرات بعد أول رفع؟
3. أي أمر يسمّي الفرع الأول main؟

الإجابات

  • أربعة — Home وAbout وProjects وContact.
  • عبر الفروع وPRs — سير عمل الفريق.
  • git init -b main — يتجنب إعادة التسمية.

الخلاصة

أنشئ مستودعًا فارغًا وارفع هيكلًا وخطط للمهام كفروع.
