فهم git add

Understanding git add

أهداف التعلم

  • أن تشرح معنى التجهيز (staging).
  • أن تجهّز كل شيء أو ملفات محددة فقط.
  • أن تفرّق بين git add . وgit add -A.
  • أن تفحص ما جُهّز.
  • أن تشرح لماذا يجب ألا تُحفظ الأسرار في commit أبدًا.

المتطلبات المسبقة

الوحدة 3 ومجلد my-first-project.

مقدمة

لا يحفظ Git كل تغيير تلقائيًا. أولًا تختار التغييرات التي تنتمي إلى اللقطة القادمة. هذا الاختيار يسمى التجهيز، والأمر git add هو أداته.

الشرح

التجهيز (Staging) يعني وضع التغييرات في منطقة التجهيز، وهي غرفة انتظار الـ commit القادم. الأمر git add لا ينشئ commit أبدًا، هو يحضّره فقط.

git add index.html يجهّز ملفًا واحدًا. وgit add index.html style.css يجهّز ملفين. وgit add . يجهّز كل تغيير في المجلد الحالي ومجلداته الفرعية: ملفات جديدة ومعدّلة ومحذوفة.

git add -A يجهّز كل التغييرات في المستودع كله أينما كنت داخله. ومن جذر المشروع يفعل . و-A الشيء نفسه، ويختلفان عند تنفيذهما داخل مجلد فرعي.

git add -p يتيح لك التجهيز قطعة قطعة. يعرض Git كل كتلة متغيرة (hunk) ويسأل Stage this hunk [y,n,q,a,d,s,e,?]?. أجب y للموافقة وn للرفض وq للخروج.

لماذا التجهيز الانتقائي؟ إن أصلحت خطأً وبدأت ميزة جديدة، فـ commitان أوضح من واحد. الملفات المحددة أو -p تتيح لك فصل العمل.

الفحص. الأمر git status يعرض الملفات المجهّزة تحت «Changes to be committed». والأمر git diff --staged يعرض بالضبط ما جُهّز. وإن عدّلت ملفًا بعد تجهيزه فسيظهر في القائمتين: الـ commit يأخذ النسخة التي جهّزتها لا تعديلك الأحدث. نفّذ git add مرة أخرى لتضمّه.

الأسرار. لا تجهّز ملفات فيها كلمات سر أو مفاتيح API أو بيانات .env. بعد حفظها في commit تبقى في التاريخ. افحص git status قبل git add ..

في VS Code. افتح Source Control (Ctrl+Shift+G). علامة + بجانب الملف تجهّزه، وعلامة + بجانب Changes تجهّزها كلها (مثل git add .)، وعلامة − تلغي التجهيز.

تشبيه من الحياة

التجهيز كاختيار الأشياء لصورة. ترتّب الأغراض التي تريدها في الإطار أولًا، ثم يأتي ضغط الزر (الـ commit).

مخطط توضيحي

الأوامر

git add index.html
git add index.html style.css
git add .
git add -A
git add -p
git status

الخيارات: . المجلد الحالي؛ -A كل التغييرات في المستودع؛ -p اختيار الكتل بشكل تفاعلي. الشكل 1 يعرض git status بعد تجهيز ملف واحد.

أخطاء شائعة وحلولها

الظن أن git add يحفظ العمل.لا يُحفظ شيء حتى تنفّذ commit.
استخدام git add . دون نظر.نفّذ git status أولًا حتى لا يمرّ سر أو ملف غير مرغوب.
التعديل بعد التجهيز ثم commit دون add جديد.نفّذ git add مرة أخرى، وإلا بقي التعديل الجديد خارج الـ commit.

تمرين عملي

في my-first-project جهّز index.html فقط. نفّذ git status. ثم نفّذ git diff --staged.

النتيجة المتوقعة

يظهر index.html تحت «Changes to be committed» ويبقى الملفان الآخران غير متتبَّعين، كما في الشكل 1.

اختبر فهمك

1. هل ينشئ git add عملية commit؟
2. أي أمر يعرض ما جُهّز؟
3. لماذا لا نحفظ ملف .env في commit؟

الإجابات

  • لا، هو يجهّز فقط — التجهيز يحضّر التغييرات، والـ commit ينشئ اللقطة.
  • git diff --staged — يقارن منطقة التجهيز بآخر commit.
  • قد يحتوي أسرارًا تبقى في التاريخ — كل ما يُحفظ في commit يبقى في التاريخ.

الخلاصة

الأمر git add يجهّز التغييرات للـ commit القادم. جهّز ملفات محددة لتحصل على commits نظيفة، وافحص بـ git status وgit diff --staged، ولا تجهّز الأسرار أبدًا.
