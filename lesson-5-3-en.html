MODULE 05 · LESSON 5.3

Exploring a GitHub repository

استكشاف مستودع GitHub

Learning objectives

  • Find files, commits and branches on GitHub.
  • Read the README on the page.
  • Name Issues and Pull requests.
  • Find visibility and URLs.

Prerequisites

Lesson 5.2.

Introduction

Your pushed project now has a web page. Learn its parts, because you will use them every day.

Explanation

Code tab: files and folders, the branch selector (main), and the green Code button with the clone URL.

The README shows below the file list, formatted. It is the front page of the project.

Commits: click the clock icon with the commit count to see every commit with message, author and date.

Branches: lists all branches. You will create more in Module 7.

Issues track tasks and bugs. Pull requests propose changes for review (Module 9).

Settings controls visibility (Public or Private), collaborators, and later GitHub Pages. Change visibility carefully.

URLs. The page address is https://github.com/USER/REPO. The .git version of it is what Git uses to clone and push.

Real-world analogy

The repository page is a shop window for your project: the front page (README), the stock list (files), the history book (commits).

Common mistakes and solutions

Making a repo public by accident.Check the visibility under Settings.
Editing files on GitHub then forgetting local.Later you must pull those changes (Module 8).
Ignoring the README.Write it early. It is the first thing people read.

Practical exercise

Open your repository on GitHub. Find: the file list, the commit count, the branch selector, the README and the Settings tab.

Expected result

You can locate all five and open the commit list showing your three commits.

Knowledge check

1. Where do you see commit history?
2. What are Pull requests for?
3. Where is visibility set?

Answers

  • The Commits link on the Code tab — The commit count opens the full history.
  • Proposing changes for review — They are how changes are reviewed and merged.
  • Settings — Settings holds Public and Private.

Summary

A GitHub repository page shows code, commits, branches, README, issues, pull requests and settings, including visibility.

Key vocabulary

READMEThe project’s front page
IssueA tracked task or bug
Pull requestA proposal to merge changes
