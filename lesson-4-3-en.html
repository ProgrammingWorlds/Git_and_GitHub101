MODULE 04 · LESSON 4.3

Reviewing Git history

مراجعة سجل Git

Learning objectives

  • Read the commit list with git log.
  • Compare changes with git diff and git diff --staged.
  • Inspect a commit with git show.

Prerequisites

Lesson 4.2.

Introduction

History is only useful if you can read it. These commands show what happened and when.

Explanation

git log lists commits, newest first. Each entry shows the full hash, author, date and message. If the list is long, Git opens a viewer: press q to leave it.

git log --oneline shows one short line per commit: a short hash and the message. (HEAD -> main) marks where you are now.

git diff shows changes you made but have not staged. git diff --staged shows changes that are staged for the next commit. Lines starting with + were added and lines starting with - were removed.

git show displays the latest commit with its changes. git show 3f2a9c1 shows a chosen commit.

git status remains your first check: it tells you what to do next.

Real-world analogy

git log is the logbook of a ship. git diff compares today’s page with what is already written.

Common mistakes and solutions

Stuck inside git log.Press q to quit the viewer.
Expecting git diff to show staged changes.Use git diff --staged for those.
Copying a full hash by hand.The first 7 characters are enough.

Practical exercise

Edit README.md and run git diff. Stage it and run git diff --staged. Then run git log --oneline.

Expected result

The first diff shows your added lines with +. After staging, only --staged shows them. The log lists your commits.

Knowledge check

1. How do you leave the git log viewer?
2. Which command shows unstaged changes?
3. What does git log --oneline show?

Answers

  • Press q — q quits the pager.
  • git diff — git diff compares your working files with the staging area.
  • One short line per commit — A short hash and the message for each commit.

Summary

git log lists history, git diff and git diff --staged compare changes, and git show inspects one commit.
