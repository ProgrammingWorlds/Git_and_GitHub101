MODULE 11 · LESSON 11.2

Ignoring files with .gitignore

تجاهل الملفات بـ .gitignore

Learning objectives

  • Explain .gitignore.
  • Write patterns.
  • Stop tracking a file already committed.

Prerequisites

Lesson 11.1.

Introduction

Some files should never be in Git: secrets, logs, system files and downloaded dependencies.

Explanation

.gitignore is a text file in the repository root. Each line is a pattern for files Git should ignore (Figure 1).

Common patterns: .env, *.log (any log file), node_modules/ (a folder), Thumbs.db, .DS_Store.

Lines starting with # are comments. A leading ! re-includes a file.

Create the file, commit it, and share it with the team so everyone ignores the same things.

Important: .gitignore only affects files Git is not tracking yet. If you already committed a file, run git rm --cached FILE, then commit. The file stays on your disk but leaves future commits.

If it was a secret, ignoring it is not enough; it is still in history (Lesson 11.3).

Check with git status that ignored files no longer appear.

Real-world analogy

.gitignore is a “do not photograph” list for a camera that otherwise photographs everything.

Common mistakes and solutions

Expecting .gitignore to untrack committed files.Use git rm --cached.
Wrong file name such as gitignore.txt.It must be .gitignore with no extension.
Ignoring too much.Keep patterns specific.

Practical exercise

Create .env with a fake value, ignore it, and confirm status does not list it.

Expected result

git status shows .gitignore but not .env.

Knowledge check

1. Where does .gitignore live?
2. Does .gitignore untrack committed files?
3. What does *.log match?

Answers

  • Repository root — Usually the root.
  • No — Use git rm --cached.
  • All .log files — * is a wildcard.

Summary

List patterns in .gitignore; use git rm --cached for files already tracked.
