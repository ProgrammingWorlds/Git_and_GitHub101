MODULE 09 · LESSON 9.2

Opening a pull request

فتح طلب دمج

Learning objectives

  • Define a pull request.
  • Open one on GitHub.
  • Write a good title and description.

Prerequisites

Lesson 9.1.

Introduction

A pull request (PR) asks the team to review and merge your branch into another branch.

Explanation

On GitHub, click Compare & pull request (or the Pull requests tab → New pull request).

Check the two branches at the top: base is where changes go (main) and compare is your branch.

Write a clear title, for example Add about page.

Write the description: what changed, why, and how to check it. Mention an issue with Closes #3 if there is one.

Look at the Files changed tab. Review your own diff before asking others.

Click Create pull request. Optionally choose reviewers on the right. Use Create draft pull request if the work is not ready.

Any new commit you push to the same branch appears in the PR automatically.

Real-world analogy

A PR is a cover letter attached to your chapter: it explains what you changed and invites feedback.

Common mistakes and solutions

Base set to the wrong branch.Check base and compare before creating.
Empty description.Always explain what and why.
Opening a PR with unrelated changes.Split into separate PRs.

Practical exercise

Open a pull request from feature/about-page into main with a title and description.

Expected result

The PR page shows your commit and “Able to merge”.

Knowledge check

1. What is a pull request?
2. Which is the base branch?
3. A draft PR means…

Answers

  • A request to review and merge a branch — PRs live on GitHub.
  • Where changes will go — Usually main.
  • Not ready for review — It signals work in progress.

Summary

A PR proposes a branch for review. Give it a clear title and description.
