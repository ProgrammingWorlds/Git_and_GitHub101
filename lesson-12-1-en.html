MODULE 12 · LESSON 12.1

Plan and start the project

التخطيط وبدء المشروع

Learning objectives

  • Read the project brief.
  • Create the repository.
  • Plan branches and tasks.

Prerequisites

Modules 1–11.

Introduction

You will build a small portfolio website and manage it like a real team project.

Explanation

Brief. A one-page site with four sections: Home, About, Projects, Contact. Plain HTML and CSS; no frameworks.

Repository. Create portfolio-website on GitHub (public, with no README), then run the commands in Figure 1. Use git init -b main so the first branch is called main.

Add a starter structure: index.html, style.css, README.md, .gitignore.

Plan. Write tasks as branches: feature/home, feature/about, feature/projects-section, feature/contact, docs/readme.

Rules. Never commit to main after the first push; every change goes through a pull request; commit messages are specific.

You can use GitHub Issues to list tasks and write Closes #1 in a PR to close one.

What the website needs. A navigation bar, a hero section with a heading and a button, an About section, a Projects section with cards, a Contact section, and a footer. Make it responsive with a viewport meta tag and a flexible grid. The folder final-project/starter has the empty skeleton and final-project/solution has one complete example to compare with afterwards.

Real-world analogy

You are the architect and the site manager at once: first the plan, then the building.

Common mistakes and solutions

Creating the repo with a README and then pushing a different history.Create it empty, or clone it instead.
Starting without a plan.List branches first.
Working on main.Branch for every task.

Expected result

Knowledge check

1. How many sections does the brief require?
2. Where do changes go after the first push?
3. Which command names the first branch main?

Answers

  • Four — Home, About, Projects, Contact.
  • Through branches and PRs — Team workflow.
  • git init -b main — It avoids later renaming.

Summary

Create an empty repo, push a skeleton, and plan tasks as branches.
