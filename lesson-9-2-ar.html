الوحدة 09 · الدرس 9.2

فتح طلب دمج (Pull Request)

Opening a pull request

أهداف التعلم

  • أن تعرّف الـ pull request.
  • أن تفتح واحدًا على GitHub.
  • أن تكتب عنوانًا ووصفًا جيدين.

المتطلبات المسبقة

الدرس 9.1.

مقدمة

الـ pull request (PR) يطلب من الفريق مراجعة فرعك ودمجه في فرع آخر.

الشرح

في GitHub اضغط Compare & pull request (أو تبويب Pull requests ← New pull request).

تحقق من الفرعين في الأعلى: base حيث تذهب التغييرات (main) وcompare فرعك.

اكتب عنوانًا واضحًا مثل Add about page.

اكتب الوصف: ماذا تغيّر ولماذا وكيف يُتحقق. اذكر issue بعبارة Closes #3 إن وُجد.

انظر تبويب Files changed. راجع الفروقات بنفسك قبل أن تطلب من غيرك.

اضغط Create pull request. ويمكنك اختيار مراجعين من اليمين. استخدم Create draft pull request إن لم يكتمل العمل.

أي commit جديد ترفعه إلى الفرع نفسه يظهر في الـ PR تلقائيًا.

تشبيه من الحياة

الـ PR رسالة تعريف مرفقة بفصلك: تشرح ما غيّرت وتدعو إلى الملاحظات.

مخطط توضيحي

الأوامر

لا حاجة لأمر Git جديد. الـ PR يعيش على GitHub وترفع الـ commits كالمعتاد.

الشكل 1 يلخّص مسار الـ pull request.

أخطاء شائعة وحلولها

ضبط base على فرع خاطئ.تحقق من base وcompare قبل الإنشاء.
وصف فارغ.اشرح دائمًا ماذا ولماذا.
فتح PR بتغييرات غير مترابطة.قسّمها إلى PRs منفصلة.

تمرين عملي

افتح pull request من feature/about-page إلى main بعنوان ووصف.

النتيجة المتوقعة

تعرض صفحة الـ PR الـ commit الخاص بك وعبارة «Able to merge».

اختبر فهمك

1. ما هو الـ pull request؟
2. ما الـ base؟
3. الـ PR من نوع draft يعني…

الإجابات

  • طلب مراجعة ودمج فرع — الـ PR على GitHub.
  • حيث ستذهب التغييرات — غالبًا main.
  • غير جاهز للمراجعة — يدل على عمل جارٍ.

الخلاصة

الـ PR يقترح فرعًا للمراجعة. أعطه عنوانًا ووصفًا واضحين.
