Understanding git add

فهم git add

Learning objectives

  • Explain what staging means.
  • Stage everything or only specific files.
  • Tell git add . from git add -A.
  • Inspect what is staged.
  • Explain why secrets must never be committed.

Prerequisites

Module 3 and the my-first-project folder.

Introduction

Git does not save every change automatically. First you choose which changes belong in the next snapshot. That choice is called staging, and git add is the command for it.

Explanation

Staging means placing changes in the staging area, the waiting room for the next commit. git add never creates a commit. It only prepares one.

git add index.html stages one file. git add index.html style.css stages two. git add . stages every change in the current folder and its subfolders: new, modified and deleted files.

git add -A stages all changes in the whole repository, wherever you are inside it. From the project root, . and -A do the same thing. They differ when you run them inside a subfolder.

git add -p lets you stage piece by piece. Git shows each changed block (a hunk) and asks Stage this hunk [y,n,q,a,d,s,e,?]?. Answer y for yes, n for no, and q to quit.

Why stage selectively? If you fixed a bug and also started a new feature, two commits are clearer than one. Specific files or -p let you split the work.

Inspect. git status lists staged files under “Changes to be committed”. git diff --staged shows exactly what is staged. If you edit a file after staging it, that file appears in both lists: the commit takes the version you staged, not your newer edit. Run git add again to include it.

Secrets. Never stage files with passwords, API keys or .env data. Once committed they stay in history. Check git status before git add ..

In VS Code. Open Source Control (Ctrl+Shift+G). The + next to a file stages it. The + next to Changes stages all of them (like git add .). The − unstages.

Real-world analogy

Staging is choosing items for a photo. You arrange the objects you want in the frame first. The shutter (the commit) comes after.

Common mistakes and solutions

Thinking git add saves the work.Nothing is saved until you commit.
Using git add . without looking.Run git status first so no secret or junk file slips in.
Editing after staging and committing without adding again.Run git add again, or the new edit stays out of the commit.

Practical exercise

In my-first-project, stage only index.html. Run git status. Then run git diff --staged.

Expected result

index.html is under “Changes to be committed” and the other two files are still untracked, as in Figure 1.

Knowledge check

1. Does git add create a commit?
2. Which command shows what is staged?
3. Why not commit a .env file?

Answers

  • No, it only stages — Staging prepares changes. Commit creates the snapshot.
  • git diff --staged — It compares the staging area with the last commit.
  • It may contain secrets that stay in history — Anything committed remains in history.

Summary

git add stages changes for the next commit. Stage specific files for clean commits, check with git status and git diff --staged, and never stage secrets.
