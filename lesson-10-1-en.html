MODULE 10 · LESSON 10.1

Undo changes before you commit

التراجع قبل الـ commit

Learning objectives

  • Discard a file edit.
  • Unstage a file.
  • Save work aside with stash.

Prerequisites

Module 4.

Introduction

Most mistakes happen before a commit, and they are the easiest to fix.

Explanation

git restore index.html throws away your edits in that file and returns it to the last commit. This cannot be undone, because Git never saved those edits.

git restore --staged style.css removes a file from the staging area but keeps your edits. It is the opposite of git add.

Always run git status first so you know which files are staged and which are not.

git stash push -m "work in progress" puts your uncommitted edits in a safe drawer and gives you a clean tree. git stash list shows drawers and git stash pop brings the latest back.

Use stash when you need to switch branches or pull but are not ready to commit.

In VS Code: hover a file in Source Control; the ↶ Discard Changes button restores it, and the − button unstages. Discard asks for confirmation, and it is also irreversible.

Real-world analogy

Restore is erasing a pencil line back to the last printed page. Stash is sliding your messy desk into a drawer for later.

Common mistakes and solutions

Using restore on work you want to keep.Stash or commit first.
Confusing restore with restore --staged.The first discards edits; the second only unstages.
Forgetting stashed work.Check git stash list.

Practical exercise

Edit index.html, discard the edit. Then stage style.css and unstage it.

Expected result

git status shows index.html clean and style.css modified but not staged.

Knowledge check

1. What does git restore FILE do?
2. What does restore --staged do?
3. git stash is for…

Answers

  • Discards your edits — It is irreversible.
  • Unstages but keeps edits — It undoes git add.
  • Setting work aside — Pop brings it back.

Summary

Restore discards edits, restore --staged unstages, and stash parks work.

Key vocabulary
