فهم سير عمل Git

Understanding the Git workflow

أهداف التعلم

  • أن تسمّي الأماكن الأربعة التي قد يوجد فيها التغيير.
  • أن تميّز الملفات غير المتتبَّعة والمعدّلة والمجهّزة والمحفوظة.
  • أن تشرح add ثم commit ثم push.

المتطلبات المسبقة

الدرسان 1.1 و1.2.

مقدمة

لا يحفظ Git كل شيء تلقائيًا. أنت تختار ماذا تحفظ ومتى. وهذا الاختيار يحدث على مراحل، وتعلّمها يجعل كل أمر لاحق سهل الفهم.

الشرح

مجلد العمل (Working directory): مجلد مشروعك حيث تعدّل الملفات.

الملفات غير المتتبَّعة (Untracked) ملفات جديدة لم يرها Git بعد. والملفات المعدّلة (Modified) ملفات متتبَّعة غيّرتها منذ آخر commit.

منطقة التجهيز (Staging area): غرفة انتظار. تضع فيها التغييرات التي تريدها في الـ commit القادم. الأمر هو git add.

المستودع المحلي: التاريخ على جهازك. الأمر git commit يحفظ التغييرات المجهّزة كـ commit جديد.

المستودع البعيد: النسخة على GitHub. الأمر git push يرسل إليه الـ commits الجديدة.

سجل الـ commits هو قائمة كل الـ commits. تذكّر: التجهيز ليس حفظًا، والحفظ ليس رفعًا. كل منهما خطوة مستقلة.

تشبيه من الحياة

تجهيز طرد بريدي: تعدّل في غرفتك (مجلد العمل)، وتضع ما اخترته في الصندوق (التجهيز)، وتغلقه وتكتب عليه (commit)، ثم ترسله بالبريد (push).

مخطط توضيحي

الأوامر

ستتعلم هذه الأوامر في الوحدتين 4 و5. الآن يكفي أن تتعرف عليها: git add وgit commit -m "message" وgit push.

أخطاء شائعة وحلولها

الظن أن add يحفظ العمل.هو يجهّز التغييرات فقط. لا يُحفظ شيء حتى تنفّذ commit.
الظن أن commit يرفع إلى GitHub.الـ commit يحفظ على جهازك فقط. الرفع يتم بـ push.
توقع أن تُتتبَّع الملفات الجديدة تلقائيًا.الملفات الجديدة غير متتبَّعة حتى تضيفها بـ add.

تمرين عملي

تخيّل أنك عدّلت index.html، ثم نفّذت git add index.html، ثم git commit -m "Add homepage". اكتب في أي مرحلة يكون التغيير بعد كل إجراء من الثلاثة.

النتيجة المتوقعة

بعد التعديل: معدّل في مجلد العمل. بعد add: مجهّز. بعد commit: محفوظ في المستودع المحلي ولم يصل GitHub بعد.

اختبر فهمك

1. أي أمر يرسل الـ commits إلى GitHub؟
2. الملف الجديد الذي لم يره Git يسمى…
3. هل ينشئ git add عملية commit؟

الإجابات

  • git push — push يرفع الـ commits إلى المستودع البعيد.
  • غير متتبَّع (Untracked) — الملفات الجديدة غير متتبَّعة حتى تضيفها بـ add.
  • لا، هو يجهّز التغييرات فقط — التجهيز يحضّر التغييرات، والـ commit هو الذي ينشئ اللقطة.

الخلاصة

ينتقل التغيير من مجلد العمل إلى منطقة التجهيز (add)، ثم إلى المستودع المحلي (commit)، ثم إلى المستودع البعيد (push).
