الأمان والعادات الجيدة

Security and good habits

أهداف التعلم

  • أن تُبعد الأسرار عن Git.
  • أن تتصرف عند تسرّب token.
  • أن تتبنى عادات الـ commits والفروع.

المتطلبات المسبقة

الدرس 11.2.

مقدمة

Git يتذكر كل شيء، فأخطاء الأسرار تبقى للأبد ما لم تتصرف.

الشرح

لا تحفظ في commit كلمات سر ولا مفاتيح API ولا tokens ولا مفاتيح خاصة ولا ملفات .env.

إن سرّبت واحدًا: أولًا ألغِه أو بدّله عند المزوّد (لـ token في GitHub: Settings ← Developer settings ← Personal access tokens). حذفه من آخر commit لا يكفي لأن التاريخ ما زال يحويه. اعتبره علنيًا.

فعّل المصادقة الثنائية (2FA) في GitHub (Settings ← Password and authentication).

يستخدم هذا الكورس HTTPS مع Git Credential Manager، فلا تخزّن كلمة سر في ملف.

رسائل الـ commit: قصيرة بصيغة الأمر ومحددة — «Fix navigation spacing» لا «changes».

العادات: اسحب قبل أن تبدأ، واحفظ commits صغيرة، وغرضًا واحدًا لكل فرع، وراجع الفروقات قبل الحفظ، ولا تعمل force-push لفروع مشتركة، وأبقِ main عاملًا.

المستودعات الخاصة تخفي الكود عن العامة، لكن لا تعتمد عليها لحماية الأسرار.

تشبيه من الحياة

المفتاح المسرّب مفتاح بيت نُسخ: الحل الحقيقي تبديل القفل، لا إخفاء النسخة.

مخطط توضيحي

الأوامر

لا أوامر جديدة. راجع git diff وgit status قبل كل commit.

أخطاء شائعة وحلولها

حذف السر والاكتفاء.ألغِه.
استخدام «update» لكل رسالة.قل ما الذي تغيّر.
force-push إلى main.تجنّبه؛ استخدم revert.

تمرين عملي

اكتب خمس رسائل commit جيدة لتغييرات أجريتها في هذا الكورس.

النتيجة المتوقعة

كل رسالة أقل من 72 حرفًا وتصف تغييرًا واحدًا.

اختبر فهمك

1. أول إجراء عند تسرّب token؟
2. أيّ رسالة commit جيدة؟
3. ماذا تحمي 2FA؟

الإجابات

  • إلغاؤه أو تبديله — التاريخ يحتفظ به.
  • Fix navigation spacing — كن محددًا.
  • حسابك في GitHub — تمنع سرقة كلمة السر.

الخلاصة

أبعد الأسرار، بدّل المسرَّب، فعّل 2FA، واجعل commits واضحة وصغيرة.
