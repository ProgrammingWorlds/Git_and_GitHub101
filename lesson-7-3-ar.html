تعارضات الدمج

Merge conflicts

أهداف التعلم

  • أن تشرح لماذا تحدث التعارضات.
  • أن تقرأ علامات التعارض.
  • أن تحلّ التعارض بمحرر الدمج في VS Code.
  • أن تُنهي الدمج.

المتطلبات المسبقة

الدرس 7.2.

مقدمة

التعارض ليس خطأً. هو أن Git يطلب منك أن تقرر.

الشرح

لماذا. غيّر فرعان الأسطر نفسها بشكلين مختلفين. لا يستطيع Git تخمين أيهما يبقى.

كيف تعرف. يتوقف الدمج مع CONFLICT (content): Merge conflict in index.html. ويسرد git status الملف تحت «Unmerged paths» بحالة «both modified».

العلامات. يكتب Git النسختين في الملف. ما بين <<<<<<< HEAD و======= هو فرعك الحالي. وما بين ======= و>>>>>>> feature/homepage هو الفرع القادم (الشكل 1).

الحل. في VS Code تظهر أزرار فوق التعارض: Accept Current وAccept Incoming وAccept Both، أو افتح Resolve in Merge Editor لعرض من ثلاثة أجزاء. اختر أو ادمج، وتأكد ألا تبقى علامات.

اختبر. افتح الصفحة وتأكد أنها ما زالت تعمل.

أنهِ. نفّذ git add index.html ثم git commit (أو git merge --continue). يقترح Git رسالة دمج.

باب النجاة. الأمر git merge --abort يلغي الدمج ويعيدك إلى ما قبله.

تشبيه من الحياة

محرران أعادا كتابة الجملة نفسها. على المؤلف أن يقرأ النسختين ويكتب الجملة النهائية.

مخطط توضيحي

الأوامر

git merge feature/homepage
git status
git add index.html
git commit
git merge --abort

تمرين عملي

اقرأ مختبر هذه الوحدة وحلّ التعارض الذي ينشئه.

النتيجة المتوقعة

في الملف عنوان واحد بلا علامات، وgit status نظيف بعد commit الدمج.

اختبر فهمك

1. لماذا تحدث التعارضات؟
2. ماذا يعني HEAD بين العلامات؟
3. كيف تلغي دمجًا متعارضًا؟

الإجابات

  • غيّر فرعان الأسطر نفسها — لا يستطيع Git الاختيار تلقائيًا.
  • نسخة فرعك الحالي — الكتلة الأولى هي جانبك.
  • git merge --abort — يعيد الحالة قبل الدمج.

الخلاصة

التعارض يعني أن Git يحتاج قرارك. عدّل الملف، وأزل العلامات، واختبر، ثم add وcommit، أو ألغِ.
