MODULE 11 · LESSON 11.3

Security and good habits

الأمان والعادات الجيدة

Learning objectives

  • Keep secrets out of Git.
  • React to a leaked token.
  • Adopt commit and branch habits.

Prerequisites

Lesson 11.2.

Introduction

Git remembers everything, so mistakes with secrets live forever unless you act.

Explanation

Never commit passwords, API keys, access tokens, private keys or .env files.

If you leaked one: first revoke or rotate it at the provider (for a GitHub token: Settings → Developer settings → Personal access tokens). Removing it from the latest commit is not enough, because history still has it. Treat it as public.

Turn on two-factor authentication on GitHub (Settings → Password and authentication).

This course uses HTTPS with Git Credential Manager, so you never store a password in a file.

Commit messages: short, imperative, specific — “Fix navigation spacing”, not “changes”.

Habits: pull before you start, commit small, one purpose per branch, review the diff before committing, never force-push shared branches, and keep main working.

Private repositories hide code from the public, but do not rely on them to protect secrets.

Real-world analogy

A leaked key is a house key copied: changing the lock (rotating) is the real fix, not hiding the copy.

Common mistakes and solutions

Deleting the secret and calling it done.Revoke it.
Using “update” as every message.Say what changed.
Force-pushing main.Avoid it; use revert.

Practical exercise

Write five good commit messages for changes you have made in this course.

Expected result

Each message is under 72 characters and describes one change.

Knowledge check

1. First action when a token leaks?
2. Which is a good commit message?
3. What should 2FA protect?

Answers

  • Revoke or rotate it — History keeps it.
  • Fix navigation spacing — Be specific.
  • Your GitHub account — It blocks stolen passwords.

Summary

Keep secrets out, rotate leaks, enable 2FA, and keep commits clear and small.
