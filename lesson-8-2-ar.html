جلب التغييرات (Fetch)

Fetching changes

أهداف التعلم

  • أن تشرح fetch.
  • أن تقارن المحلي بالبعيد.
  • أن تقرأ «behind» و«ahead».

المتطلبات المسبقة

الدرس 8.1.

مقدمة

الـ fetch ينزّل العمل الجديد من GitHub دون تغيير ملفاتك. هو الطريقة الآمنة للنظر أولًا.

الشرح

عدّل أحدهم ملف README على GitHub. جهازك لا يعرف بعد.

git fetch يحدّث فروع التتبع البعيدة مثل origin/main. أما main وملفاتك فلا يتغيران.

git status يقول الآن إن فرعك behind origin/main بـ commit واحد.

افحص بـ git log --oneline main..origin/main (ما لا تملكه) أو git diff main origin/main.

«Ahead» تعني أن لديك commits لترفعها. و«behind» تعني أن عند GitHub commits لتسحبها. وإن حدثا معًا فهو «diverged».

في VS Code يعرض شريط الحالة أسهمًا بأعداد. وقائمة Source Control (…) فيها أمر Fetch.

تشبيه من الحياة

الـ fetch مثل فحص صندوق البريد وقراءة الرسائل عند الباب دون إدخالها إلى غرفتك.

مخطط توضيحي

الأوامر

git fetch
git status
git log --oneline main..origin/main

الشكل 1 يعرض الخرج بعد fetch.

أخطاء شائعة وحلولها

الظن أن fetch يغيّر ملفاتك.لا يغيّرها. يحدّث origin/* فقط.
نسيان fetch قبل المقارنة.يستخدم status آخر نسخة معروفة من origin.
الذعر من «diverged».اسحب وحلّ التعارض (الدرس 8.3).

تمرين عملي

عدّل README.md على GitHub (أيقونة القلم) واحفظ هناك، ثم نفّذ fetch محليًا.

النتيجة المتوقعة

يقول git status إنك behind بـ commit واحد وREADME عندك لم يتغير.

اختبر فهمك

1. هل يغيّر fetch ملفات العمل؟
2. ماذا يعني «behind by 1»؟
3. أي فرع يحدّثه fetch؟

الإجابات

  • لا — يحدّث فروع التتبع فقط.
  • عند GitHub commit ينقصك — تحتاج pull.
  • origin/main — فرع التتبع البعيد.

الخلاصة

الـ fetch ينظر إلى GitHub بأمان. ثم يخبرك status إن كنت behind أو ahead.

مصطلحات أساسية

fetchتنزيل تغييرات بعيدة دون دمج
behindعند البعيد commits تنقصك
aheadعندك commits لترفعها
