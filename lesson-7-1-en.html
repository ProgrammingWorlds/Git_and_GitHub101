Understanding branches

فهم الفروع

Learning objectives

  • Define a branch.
  • Explain why branches exist.
  • Name feature and bug-fix branches.
  • Explain how commits relate to branches.

Prerequisites

Module 6.

Introduction

Imagine trying a risky idea without touching your working project. Branches make that possible.

Explanation

A branch is a movable label that points to a commit. Making one costs almost nothing, because Git does not copy files.

main is the default branch. Keep it stable and working.

A feature branch holds new work, for example feature/homepage. A bug-fix branch holds a repair, for example fix/nav-spacing.

Parallel development. You can work on a feature while a teammate fixes a bug, each on a separate branch, without disturbing each other.

Commits and branches. When you commit, the current branch label moves forward to the new commit. HEAD tells Git which branch you are on. When ready, you merge the branch back into main (Lesson 7.2).

Real-world analogy

A branch is a photocopy of a draft you scribble on. If the idea is good, you copy the changes into the original. If not, you throw the copy away.

Knowledge check

1. What is a branch?
2. What is a feature branch for?
3. What does HEAD show?

Answers

  • A pointer to a commit — Branches are lightweight pointers.
  • New work — It isolates new work.
  • The branch/commit you are on — HEAD is your current position.

Summary

Branches let you work in parallel safely. Commits move the current branch forward, and merges combine branches.
