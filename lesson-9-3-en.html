MODULE 09 · LESSON 9.3

Review, merge and clean up

المراجعة والدمج والتنظيف

Learning objectives

  • Review a PR.
  • Merge on GitHub.
  • Update local main and delete the branch.

Prerequisites

Lesson 9.2.

Introduction

A review makes the code better, and merging makes it official.

Explanation

Reviewers open Files changed, hover a line, click the blue +, and write a comment. Review changes lets them Comment, Approve or Request changes.

To answer feedback, commit to the same branch and push. The PR updates itself.

When approved and checks pass, click Merge pull request then Confirm merge. Other options are Squash and merge (one commit) and Rebase and merge. This course uses the default merge.

GitHub shows Delete branch. Click it; the work is safe in main.

Locally: git switch main, git pull (Figure 1), then git branch -d feature/about-page.

If the PR shows conflicts, pull main into your branch (git pull origin main while on your branch), resolve them as in Lesson 7.3, and push.

Be kind in reviews: comment on the work, suggest, and explain.

Real-world analogy

The editor reads your chapter, leaves notes, and finally approves it into the book. You then update your own copy of the book.

Commands

git switch main

Optional: git push origin --delete feature/about-page removes the remote branch if GitHub did not.

Common mistakes and solutions

Forgetting to pull after merging on GitHub.Your local main is still old until you pull.
Merging your own PR without review in a team.Follow team rules.
Deleting a branch before it is merged.Merge first.

Practical exercise

Merge your PR, delete the branch on GitHub, pull main locally, and delete the local branch.

Expected result

about.html exists on main locally and git branch shows only main.

Knowledge check

1. Who clicks Merge pull request?
2. After merging on GitHub you should…
3. Request changes means…

Answers

  • Someone with permission after approval — Teams define the rules.
  • Pull main locally — Sync your local copy.
  • Fixes are needed before merge — Update and push.

Summary

Review, approve, merge, delete the branch, then pull main.
