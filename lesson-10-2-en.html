MODULE 10 · LESSON 10.2

Fix or revert a commit

تعديل commit أو عكسه

Learning objectives

  • Amend the last commit.
  • Revert a commit.
  • Choose between amend and revert.

Prerequisites

Lesson 10.1.

Introduction

Sometimes the mistake is already in a commit. The right tool depends on whether you pushed it.

Explanation

Not pushed yet. git commit --amend -m "Better message" replaces the last commit. To add a forgotten file, git add file first, then amend.

Amend rewrites the commit (it gets a new ID). Never amend a commit others may already have.

Already pushed or shared. git revert HEAD creates a new commit that cancels the old one. History stays honest and safe for everyone.

To revert an older commit, use its ID from git log --oneline: git revert 8d2e5b1.

Reverts can conflict; resolve as in Lesson 7.3 and run git revert --continue.

After a revert, git push as usual.

Real-world analogy

Amend is fixing a typo in a letter before posting it. Revert is sending a second letter that cancels the first.

Common mistakes and solutions

Amending after push.Use revert; amending needs a force push, which is risky.
Reverting the wrong ID.Check git log --oneline.
Expecting revert to delete history.It adds a new commit.

Practical exercise

Make a commit with a typo in the message, amend it. Then revert your last commit.

Expected result

git log --oneline shows the revert commit on top.

Knowledge check

1. Which is safe for pushed commits?
2. What does amend change?
3. Does revert delete history?

Answers

  • git revert — Revert adds a new commit.
  • The last commit — It rewrites it.
  • No — It adds a cancelling commit.

Summary

Amend before pushing, revert after pushing.
