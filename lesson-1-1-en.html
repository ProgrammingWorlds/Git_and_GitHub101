MODULE 01 · LESSON 1.1

What is version control?

ما هو التحكم بالإصدارات؟

Learning objectives

  • Explain what version control is in your own words.
  • Describe three problems caused by copying project folders by hand.
  • Explain how Git records changes as a chain of commits.
  • Tell the difference between local and distributed version control.

Prerequisites

None. You only need a computer and a project, even a simple text file, that you have edited more than once.

Introduction

Imagine you are writing an important report. On Monday you save report.docx. On Tuesday you change it and save report_final.docx. By Friday you have report_final2.docx and report_REAL_final.docx, and you are not sure which one is right. Version control solves exactly this problem, and it does it for every file in a project at once.

Explanation

Version control is a system that records every change made to a set of files, who made it, when, and why. You can go back to any earlier moment, compare two moments, and work with other people without overwriting each other.

Why developers need it. Code changes constantly. A new feature can break something that worked yesterday. With version control you can see exactly what changed and undo it safely. Teams also need it: five people can edit the same project and combine their work.

The problem with copying folders. Copies take space, names become confusing, nothing explains why a copy exists, and two people copying the same folder can never merge their changes automatically.

How Git works. Git does not keep random copies. When you tell it to, it saves a commit: a snapshot of your project plus a message and an author. Each commit points to the one before it, so your history is a chain you can walk backwards.

Local and distributed. Older systems kept the history on one central server. Git is distributed: every developer has the full history on their own computer. You can work offline, and if a server is lost, any copy can restore it.

Real-world analogy

Think of a video game with save slots. Each save is a moment you can return to. A commit is a save point for your project, and the message is the label you write on it, such as “Before the boss fight”.

Common mistakes and solutions

“Git is a backup tool.”Git records meaningful changes you choose to save. Keep real backups too.
“I must be online to use Git.”Git works fully offline. You only need internet to share with GitHub.
“Version control is only for big teams.”It helps a single person from the first day of a project.

Practical exercise

Find a project or document you have edited many times. Write down three situations where you wished you could go back or compare versions. For each one, note which Git idea (history, commit, or sharing) would help.

Expected result

A short list of three real situations, each matched to an idea from this lesson. There is no right or wrong list. It prepares you for Lesson 1.2.

Knowledge check

1. What does a commit store?
2. Why is Git called distributed?
3. Which is a problem of copying folders by hand?

Answers

  • A snapshot of the project, a message, and an author — A commit is a snapshot with a message and author, linked to the commit before it.
  • Every developer has the full history locally — Each copy contains the whole history, so work does not depend on one central server.
  • Unclear names and no explanation of changes — Names like final2 do not say what changed or why, and copies cannot be merged automatically.

Summary

Version control records the history of a project. Git saves snapshots called commits, keeps the full history on every computer, and lets you return to any point or combine work from several people.

Key vocabulary

Version controlA system that records changes to files over time
CommitA saved snapshot with a message and author
HistoryThe chain of commits in a project
DistributedEvery copy holds the full history
